# Mono Suite 開発・リリース方針

更新日：2026-09-14
状態：Spaceの基準保存・Suite内整理は完了。Docの独立移行、Lib、デスクトップアプリは未実施。現在地と作業順序は[開発計画](DEVELOPMENT-PLAN.md)を正とする。

## 1. 製品の位置づけ

**中心目標は、1つの原稿からSpaceで発表し、Doc形式のHTML・PDFを配布できること。** Spaceで発表資料を作り始める場合と、Docで配布資料を作り始める場合の両方を支える。細かな配置は自動とし、利用者は原稿と少数の設定に集中する。

Spaceの画面を印刷するのではなく、同じMarkdownとアセットをDocの組版で描き直す。出力用の別原稿を手動管理することは要求しない。両方のプレビューを往復して内容を整える。これは統合目標であり、現状の実装済み機能ではない。

初期の配布単位は **Mono Suiteという1つのデスクトップアプリ**。内部を3モジュールに分ける。3つの独立したインストーラーやサービスは作らない。

| モジュール | 責務 | 出力・操作 |
|---|---|---|
| Mono Lib | 文書一覧、インポート、アセット管理 | 原稿を開く、素材を取り込む |
| Mono Doc | 読むためのレイアウト | 単一HTML、PDF |
| Mono Space | 話すための空間配置 | 空間プレゼンテーションの単一HTML |

Libで文書を開き、Doc／Spaceのプレビューを切り替えて出力する。Libを常駐サーバーや必須の独自データベースにしない。CLIからも変換処理を利用できる構造を維持する。

現リポジトリで確認済みの実装はMono Space。Docは別プロジェクトから独立移行し、既存CLI・Playwright PDFを維持する。参照仕様にあるプレゼンテーション・対話機能の実装状況は、対象版を確定して照合する。詳細は[Doc仕様レビュー](MONO-DOC-INTEGRATION.md)を参照。PDFの責務はDocに置き、移行時に既存機能を一括削除・置換しない。

## 2. 制作データと配布物

制作データは通常のフォルダーとする。

```text
教材/
  document.md
  assets/
  mono.json
  exports/
```

- Markdownと相対参照のアセットが原本。外部エディターで編集できる。
- `mono.json`はテーマ、出力設定、形式バージョンなどの任意設定。未配置でも既定値で動作させる。現段階では未実装の案。
- `exports/`にHTML・PDFを生成する。単一HTMLは配布形式であり、ソースコードや制作データを単一ファイルに制限しない。
- Libの索引やキャッシュは再生成可能にする。素材は文書フォルダーだけで持ち運べることを優先し、初期はライブラリ全体の重複排除を行わない。
- 出力の閲覧にはMono Suiteを要求しない。ネットワーク依存の有無を出力仕様で明示する。

## 3. 共有範囲

将来はインポート → Markdown＋アセット → 共通解析 → Doc／Space別の描画、という一方向の処理を目指す。初期統合は既存の解析器を別々に維持し、ファイル・アセット・処理結果を受け渡す薄い共通窓口から始める。共通AST完成をリリースの前提にしない。

共有するのは段落、見出し、リスト、表、コード、数式、画像、リンクの解析と素材処理。Docの改ページとSpaceの章配置・フォーカスは共有しない。現在のSpaceのノード構造をそのまま共通文書モデルに固定しない。

テーマは色・書体などを共有し、用途別の文字サイズ・余白・配置は各描画モジュールが持つ。共通化は実際に双方で使う部分から行い、移行時に全面的な書き換えをしない。

### 同じ原稿を出力する際のルール

- 見出し・本文・画像・表・コード・数式・リンクを保持する。Docの読む順序はMarkdownの記述順に固定する。
- Spaceの横並びの章はDocでは縦に流す。比較は紙面に収まれば並列、狭ければ縦配置とし、工程の順序は保持する。
- 接続線のラベルと参照関係は、Docでも注記や参照として残す。線を省略しても情報を失わない。
- カメラ・フォーカス・発表順はSpace専用。Docの改ページ・印刷余白はDoc専用で、共通本文を書き換えない。
- 未対応の内容は黙って捨てず、内容を保持する代替表現を用意する。内容欠落を伴う場合は警告のみで配布成功にせず、生成を失敗とする。対応範囲内の原稿は内容欠落なしで出力することを検証する。
- 発表用の短い語句から説明文を自動補完しない。配布資料の説明量はプレビューで確認する。出力先による本文の条件表示記法は初期範囲に含めない。

## 4. インポート

Mono、Craft TextBundle、Decksetなどは専用モジュールで扱う。共通の戻り値は変換原稿、コピーしたアセット、変換レポートとする。元アプリの全機能・テーマ再現は約束しない。

現在のSpaceのMono変換は旧コンポーネント記法を主対象とする。最新Docの`:::`レイアウト等への完全対応は未実装。共通原稿の無損失切り替えを現時点の機能として案内しない。Docの投票・認証・同期サーバーは任意機能として別に扱い、Libや静的出力の必須依存にしない。

原本を変更せず取り込む。初期の再インポートは新しい版として扱い、編集済み原稿への自動マージは行わない。外部プラグイン実行・自動探索・マーケットプレイスは初期範囲外。

## 5. 配布技術

macOSを先行対象とし、Electronを第一候補に小さな配布試作で確認する。ChromiumとNode.jsを同梱でき、プレビューと数式処理を揃えやすい。容量増加を受け入れる代わりに描画検証を集中させる。既存Python処理はまず同梱して使い、利用者にPythonやnpmの準備を要求しない。

Tauriは代替候補だが、OSのWebViewによる描画差と追加ランタイムの同梱負担を比較して判断する。Electron採用は実装済みの決定ではない。

DocのPDFは仕様にあるPlaywright経路をまず維持し、ElectronのPDF APIへ置換しない。アプリ外枠とPDFエンジンを別の判断とし、ブラウザーの二重同梱・容量・更新負担を配布試作で評価する。

取り込んだ文書にはNode.jsやファイル操作権限を渡さない。デスクトップの操作権限と文書プレビューを分離し、Markdownやリンクがアプリの命令として実行されない境界を設ける。

## 6. 段階的リリース

| 段階 | 内容 | 完了条件 |
|---|---|---|
| v0.1 開発基準点 | 現在のSpaceを整理・記録 | 新規リポジトリで再現可能。既知の問題を明記 |
| B1 仕様整理 | Doc仕様の採用候補・未決事項、共通契約案 | 対応表案と検証ケースを整理 |
| B2〜B3 独立移行・契約検証 | 対象Docを独立移行し、原稿位置・診断・入力版を検証 | 対象版を記録し、既存CLI・HTML・PDFが再現できる |
| 最初の統合成果 | Space原稿からDoc HTML・PDF、配布セット生成処理 | 同じ入力版の内容・順序・参照を保持し、部分失敗で既存セットを壊さない |
| macOS試用版 | 位置保持切り替え、保存時プレビュー、配布セットUI | 発表・配布どちらからも制作でき、更新失敗時も直前の表示を維持 |
| 正式版 | 形式と対応範囲の固定、配布整備 | 保存・更新・表示・出力の受け入れ条件を満たす |

v0.1は現在の開発スナップショットを表す。Suiteの3モジュール完成や一般公開品質を意味しない。初期はSuite全体でバージョンを揃える。クラウド同期、共同編集、高度なエディターは初回リリースに含めない。

5つの追加案の実装時期と事前設計は[開発計画](DEVELOPMENT-PLAN.md)を正とする。作例は初期検証にも使い、コピー／挿入UIは試用後に追加する。配布資料からSpaceへの公開リンク・QRは初回リリース後とし、全案を初回の必須条件にしない。

## 7. リリース判定

- 新しいチェックアウトから依存関係を復元し、標準文書・数式を生成できる。
- 同一のSpace原稿からSpace HTML、Doc HTML、Doc PDFを生成し、本文・素材・比較・工程・参照の欠落がないことを確認する。Docの順序は原稿順とし、Spaceの発表順変更に影響されない。
- Docから作り始める文書も既存の文書生成・PDF経路で利用できる。未対応のモジュール固有記法は警告される。
- 日本語、表、画像、コード、数式、インポートを固定の検証セットにする。
- 単体テストに加え、生成HTMLの実ブラウザ表示、スクリーンショット、フォーカス・キー操作を確認する。
- Spaceの通常・数式の俯瞰／フォーカスは9月14日に目視確認済み。変更後の画面も対象にし、テスト成功だけで表示正常と判断しない。
- DocのPDFでは、macOSのプレビューからコピーしたPythonコードを原文と比較し、改行・インデントを検証する。PDF APIの存在だけで品質保証しない。
- 同梱素材、フォント、依存ライブラリのライセンスと公開範囲を確認する。
- インストール、署名・公証、更新後の文書互換性を対象環境で確認する。

具体的なリポジトリ移行手順は[Space移行・整理記録](../../modules/space/docs/MIGRATION.md)を参照。
