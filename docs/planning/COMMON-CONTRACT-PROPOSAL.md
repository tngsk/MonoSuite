# Mono Suite 共通契約仕様書（段階B3検証済み）

更新日：2026-09-14
状態：段階B3検証完了。検証レポート STAGE-B3-VERIFICATION-REPORT.md に基づき確定。

## 1. 基本原則

1. 単一原稿の多面展開：1つのMarkdownファイルと相対参照アセットから、発表用Space HTML、配布用Doc HTML、配布用Doc PDFの3形式を出力する。出力形式ごとの別原稿手動管理は要求しない。
2. 疎結合な統合窓口：共通ASTへの全面依存を避け、各モジュールが独立した解析器を保持したまま、共通の要素対応表と診断規準を介して連携する。
3. 提示順と読書順の分離：Spaceにおけるカメラ遷移やフォーカス順序（空間配置）と、Docにおける先頭からの線形な通読順序（縦スクロールおよびページ組版）を明確に区別し、本文順序の破壊を防ぐ。

## 2. 共通要素の対応表（検証済み確定版）

| 要素 | Space仕様（確定） | Doc仕様（検証済み） | 共通契約仕様 | 代替・非対応時の振る舞い |
|---|---|---|---|---|
| 本文（段落） | 最大512px、空行区切り、通常折り返し（text-wrap:wrap） | 本文42em、両端揃え（justify）、pretty折り返し | Markdown空行区切りを厳格に共有。組版規則・幅は各モジュールが独立管理 | 原文テキストを無損失で保持 |
| 見出し階層 | H1タイトル、H2横の章、H3縦の話題、H4以下は本文内小見出し | H1〜H6の標準階層 | H1〜H3をセクション境界として共有。H4以降は本文内小見出しとして通読順を保持 | 明示ID（{#id}）を推奨。未指定時は出現順連番（n{k} と _{k}）で1対1対応 |
| 画像 | 最大3列CSS Grid、アセット相対参照 | 標準画像配置、Base64埋め込み | 相対パス解決とハッシュ名管理を共通化 | 必須画像欠落時は共通層で検知し生成失敗（Failure）として中断 |
| 表 | 768px幅、GFMパイプ表構文 | 標準表スタイル | パイプ区切り表の構造とインライン装飾を保持 | 構文不正時は通常テキストとして保持 |
| コード | 言語指定、装飾なしプレーン表示 | シンタックスハイライト、コピー | 原文のインデント・改行・空白を完全保持。印刷コピー品質を保証 | ハイライト失敗時はプレーン表示に退避 |
| 数式 | MathJaxによる事前SVG生成、TeXコピー対応 | MathJaxによる事前SVG生成 | 事前SVG生成を共通標準とし、外部フォント・外部通信に依存しない描画を担保 | 構文エラー時は共通層で検知し生成中止 |
| 比較 | ::layout compare（2〜3項目の等幅並列） | 通常の段落テキストとして保持 | Spaceは並列空間配置、Docは順序を壊さず段落保持（段階CでDoc用コンポーネント化を検討） | 3項目以内を推奨 |
| 工程 | ::layout flow（横並び工程ボックスと矢印） | 通常の段落テキストとして保持 | Spaceは横配置、Docは順序を壊さず段落保持 | 順序関係を損なわずに線形化 |
| 接続線 | ::connect a -> b \| ラベル | mono-connectorカスタム要素 | SpaceはSVG接続線描画、Docはmono-connector（印刷時非表示）として構造保持 | ラベルテキストを無損失で保持 |
| 書式装飾 | 太字、リンク、インラインコード | 太字、リンク、コード、==マーカー==等 | 標準Markdown（太字・リンク・コード）を共通基盤とする | Doc固有の装飾記法はSpaceでプレーン表示または未解釈テキストとして保持 |

## 3. 診断規則（Diagnostics Contract）

生成処理の結果は以下の3分類で厳格に判定し、不完全な成果物の配布を防ぐ。段階Cの共通パイプラインで統括制御する。

1. 成功（Success）：
   全要素が正常に変換され、画像・アセットがすべて揃い、出力完全性が確認された状態。
2. 警告付き成功（Warning）：
   OGP取得失敗による通常リンクへの縮退、またはDoc固有記法のSpaceでのプレーン化など、本文情報や構造が欠落することなく代替表現が適用された状態。プレビュー表示および単体出力は許容する。
3. 生成失敗（Failure）：
   必須画像の欠落、数式構文の破損、見出しIDの重複、未対応記法による本文脱落が発生した状態。配布セットの更新を直ちに中断し、既存の正常な成果物を保護する。

## 4. 原稿位置と入力版の契約

1. 原稿位置マッピング：
   SpaceとDocの相互切り替えを支えるため、見出し単位での位置対応テーブルを保持する。明示ID（{#id}）が存在する場合は完全一致で照合し、未指定時は出現順連番（Spaceの n{k} と Docの _{k}）により1対1で対応づける。
2. 入力版の同一性：
   1回の生成単位において、原稿テキストのハッシュ、参照アセット一覧、および出力設定を単一のビルド識別子（Build ID）で固定する。Space用HTML、Doc用HTML、Doc用PDFは必ず同一のビルド識別子から派生させ、版の不一致を排除する。

   モジュール独自記法の混在（代替表現・互換性検証用）。
