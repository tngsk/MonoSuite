# Mono Suite 共通契約案（段階B1）

更新日：2026-09-14
状態：段階B1仕様整理成果物。現リポジトリ内の仕様レビューに基づく提案。Docの実装動作は未検証。

## 1. 基本原則

1. 単一原稿の多面展開：1つのMarkdownファイルと相対参照アセットから、発表用Space HTML、配布用Doc HTML、配布用Doc PDFの3形式を出力する。出力形式ごとの別原稿手動管理は要求しない。
2. 疎結合な統合窓口：共通ASTへの全面依存を避け、各モジュールが独立した解析器を保持したまま、共通の要素対応表と診断規準を介して連携する。
3. 提示順と読書順の分離：Spaceにおけるカメラ遷移やフォーカス順序（空間配置）と、Docにおける先頭からの線形な通読順序（縦スクロールおよびページ組版）を明確に区別し、本文順序の破壊を防ぐ。

## 2. 共通要素の対応表案

| 要素 | Space仕様（確定） | Doc想定仕様（採用候補） | 共通契約案（B1） | 代替・非対応時の振る舞い |
|---|---|---|---|---|
| 本文（段落） | 最大512px、空行区切り、通常折り返し（text-wrap:wrap） | 本文42em、両端揃え（justify）、pretty折り返し | Markdown空行区切りを厳格に共有。組版規則・幅は各モジュールが独立管理 | 原文テキストを無損失で保持 |
| 見出し階層 | H1タイトル、H2横の章、H3縦の話題、H4以下は本文内小見出し | H1〜H6の標準階層 | H1〜H3をセクション境界として共有。H4以降は本文内小見出しとして通読順を保持 | 階層の飛びは警告対象とし順序を維持 |
| 画像 | 最大3列CSS Grid、アセット相対参照 | 標準画像配置、段組 | 相対パス解決とハッシュ名管理を共通化 | 必須画像欠落は警告ではなく生成失敗 |
| 表 | 768px幅、GFMパイプ表構文 | 標準表スタイル | パイプ区切り表の構造とインライン装飾を保持 | 構文不正時は通常テキストとして保持 |
| コード | 言語指定、装飾なしプレーン表示 | シンタックスハイライト、コピー | 原文のインデント・改行・空白を完全保持。印刷コピー品質を保証 | ハイライト失敗時はプレーン表示に退避 |
| 数式 | MathJaxによる事前SVG生成、TeXコピー対応 | 参照仕様に記載なし（未確認） | 事前SVG生成を共通標準とし、外部フォント・外部通信に依存しない描画を担保 | 変換エラー時は行番号を通知し生成中止 |
| 比較 | ::layout compare（2〜3項目の等幅並列） | ::: compare（2〜3カラム等幅） | Spaceは並列空間配置、Docは紙面幅に応じた並列または縦配置で順序保持 | 子要素が4以上の場合は警告付きで縦配置 |
| 工程 | ::layout flow（横並び工程ボックスと矢印） | ::: flow等（未確認） | Spaceは横配置、Docは縦フローまたは番号付き工程として保持 | 順序関係を損なわずに線形化 |
| 接続線 | ::connect a -> b \| ラベル | #id参照線、tone属性 | SpaceはSVG接続線、Docは本文末尾または注記（例: 関連: ラベル）としてテキスト保持 | 描画不能時もラベルテキストを欠落させない |
| 書式装飾 | 太字、リンク、インラインコード | ==マーカー==、++下線++、{{注釈}} | 標準Markdown（太字・リンク・コード）を共通基盤とする | モジュール固有記法は内容のみ保持または明示警告 |

## 3. 診断規則（Diagnostics Contract）

生成処理の結果は以下の3分類で厳格に判定し、不完全な成果物の配布を防ぐ。

1. 成功（Success）：
   全要素が正常に変換され、画像・アセットがすべて揃い、出力完全性が確認された状態。
2. 警告付き成功（Warning）：
   OGP取得失敗による通常リンクへの縮退など、本文情報や構造が欠落することなく代替表現が適用された状態。プレビュー表示および単体出力は許容する。
3. 生成失敗（Failure）：
   必須画像の欠落、数式構文の破損、未対応記法による本文脱落が発生した状態。配布セットの更新を直ちに中断し、既存の正常な成果物を保護する。

## 4. 原稿位置と入力版の契約

1. 原稿位置マッピング：
   SpaceとDocの相互切り替えを支えるため、見出し単位での位置対応テーブルを保持する。編集に伴う見出し変更に対しては、明示ID（{#id}）を最優先とし、未指定時は階層構造と文字列ハッシュで直前位置を追跡する。
2. 入力版の同一性：
   1回の生成単位において、原稿テキストのハッシュ、参照アセット一覧、および出力設定を単一のビルド識別子（Build ID）で固定する。Space用HTML、Doc用HTML、Doc用PDFは必ず同一のビルド識別子から派生させ、版の不一致を排除する。

## 5. 段階B3に向けた検証要件（Fixture計画）

現行の候補原稿 tests/fixtures/integration/document.md に対し、段階B3（契約検証）までに以下の検証ケースを追加整備する。

1. 正常系ケース：
   日本語組版、パイプ表、コードブロック、SVG数式、比較2項目、工程2項目、ラベル付き接続線。
2. 警告系代替ケース：
   接続線ラベルのテキスト注記化、未対応インライン装飾のプレーンテキスト化。
3. 異常系失敗ケース：
   参照先画像が存在しない状態、数式の構文エラー、重複見出しID、未定義IDへの接続線指定。

これらを体系的なテストスイートとして固定し、段階B2で移行されるDoc実装との照合判定に供する。
