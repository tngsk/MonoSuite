## 1. 段階Dの目的と背景

段階D（制作環境の試用版）は、発表用スライド（Space）と配布用文書（Doc）の執筆体験を単一の統合環境として確立し、執筆者がストレスなく両形式の内容整合性を確認できるローカル開発基盤を提供することを目的とする。従来の制作工程では、スライド用と文書用で別々のツールを起動して原稿の重複編集を強いられるか、ビルドのたびに重厚なPDF生成待ちが発生して執筆のリズムが寸断されるという深刻なアクセシビリティの乖離が存在していた。この課題に対し、本段階では外部エディターによるMarkdown保存をトリガーとした0.4秒台の超高速自動プレビュー、全画面表示と瞬時のSpaceおよびDocの相互切り替え、ならびにオンデマンドの完全配布セット書き出しを実現する軽量サーバー環境をリデザインした。これにより、執筆者は手元の慣れ親しんだエディターで執筆に集中しながら、ブラウザ上でリアルタイムに発表用・配布用双方の仕上がりを行き来できる実用的な制作フローを確立した。

## 2. 実装アーキテクチャと主要コンポーネント

段階Dの実装は、単一責任の原則に基づき、外部ライブラリへの過度な依存を排してPython標準のネットワーク・並行処理モジュールを活用した堅牢な設計を採用した。

1. 統合プレビューシェル（src/mono_suite/shell/）：
   Monoコンセプトに基づき、無彩色かつ繊細なミニマルデザインを採用したWebフロントエンド。画面上部の極細ボーダーと控えめなヘッダー（40px高）、シンプルなSpaceおよびDocのビュー切り替えスイッチ、極小の接続ステータスドット、および完全配布PDF書き出しボタンで構成される。
2. 表示切り替えおよびイベント制御スクリプト（src/mono_suite/shell/sync.js）：
   初期検討で見出し位置同期が検証されたものの、非同期DOM構築タイミング依存や見出し改名・削除時の追従負荷を考慮して位置同期機能は保留とし、確実で高速な純粋ビュー切り替え（CSSのactive/hidden切り替え）へと簡素化・整流化した。Server-Sent Events（SSE）受信時には、タイムスタンプ付きキャッシュバスターによるiframeの再読み込みのみを迅速に実行する。
3. ローカル開発サーバー（src/mono_suite/server.py）：
   Python標準のHTTPServerを拡張したDevServer基盤。ポート競合時に例外終了せず、8000番から順次空きポートを自動探索してバインドするフォールバック機構を備える。ソケットの再利用（allow_reuse_address）と安全なshutdownおよびserver_closeを徹底し、プロセスの再起動信頼性を高めた。
4. ファイル保存監視モジュール（src/mono_suite/watcher.py）：
   指定されたMarkdown原稿および同一階層の関連アセット（画像等）の更新日時（mtime）を独立スレッドで監視するFileWatcher。外部エディターによる保存を検知すると、PDF生成を省略した--no-pdfパイプラインを即座に呼び出し、生成完了後にSSE通知キューへリロードシグナルを発行する。
5. ビルド排他制御（src/mono_suite/cli.py）：
   ブラウザUIからの完全ビルド（POST /api/build）実行中にファイル保存が検知された場合、非ブロッキングロック（threading.Lock）により保存検知処理を安全にスキップする機構を配備した。これにより、同一出力ディレクトリに対する並行書き込みやアトミック置換の競合（Race condition）を未然に防止した。
6. CLIサブコマンドの拡張（src/mono_suite/cli.py）：
   制作監視サーバーを起動するmono devコマンド、および配布セットをプレビュー配信するmono serveコマンドを実装。バインドされた実ポート番号を取得してブラウザを自動オープンする。
7. エディター統合仕様（.vscode/tasks.json および package.json）：
   Visual Studio Code環境での制作体験を最適化するため、アクティブ原稿のビルド（既定ビルドタスク、Cmd+Shift+B）、標準サンプルのビルド、制作サーバー起動（mono dev）、静的配信（mono serve）、およびテスト実行（pytest）を登録したtasks.jsonを正式仕様として配備した。

## 3. 整流化タスクと検証データ

段階Dの実装後に実施した詳細検証およびヒアリングに基づき、以下の整流化タスクを実施した。

1. Monoコンセプトに基づくUIの繊細化：
   派手なグラデーションや強烈なアクセントカラーを完全に廃止し、暗色の洗練された背景（#09090b, #0d0d10）、繊細なボーダーライン（rgba(255, 255, 255, 0.08)）、抑制された等幅フォントおよびサンセリフフォントの組み合わせによる静謐なデザインへと刷新した。
2. 位置同期機能の保留とコード削減：
   iframeを介した要素検索やDOMイベント発火、スクロール位置計算を全面的に削除した。これにより、JavaScriptエラーの潜在リスクやブラウザごとの動作差異を根絶し、瞬時のビュー切り替えを実現した。
3. 空きポート自動探索の実装：
   ポート8000または8080が既存プロセスにより占有されている場合、最大50回までポート番号を自動インクリメントして空きポートを探索・バインドするロジックを配備した。これにより、Address already in use例外によるプロセスクラッシュを完全に防止した。
4. 完全ビルド実行中の保存スキップ排他制御：
   完全ビルド実行中にエディター保存が発生しても、ビルド処理を乱すことなくスキップ警告を出力して成果物の破損を防止する動作を単体テストにて実証した。
5. VS Codeタスク構成の正式仕様化：
   .vscode/tasks.json に登録された7つのタスクを環境セットアップガイドおよび開発計画書に明文化し、エディター連携を正式な制作環境仕様として組み入れた。
6. 見出し前テキスト（キャッチコピー等）の先頭見出し自動合流：
   実務原稿において大見出しの前方に配置されるキャッチコピー、講義名、日付等のプリアンブルテキストを検出し、Space向け前処理において最初に出現する見出しの本文冒頭へ自動合流させる機構（merge_preamble_for_space）を実装した。これにより、最初に見出しを記述してくださいというSpaceパーサーの制約クラッシュを完全解消した。
7. SVGベクター画像対応およびmono-doc実行パス解決の堅牢化：
   実務原稿で多用されるSVG画像（image/svg+xml）をSpace画像レンダラーの許可MIMEタイプに追加し、Base64埋め込みを可能とした。また、外部フォルダーやエディタータスクから起動された際にPATH欠落でmono-docが見失われる問題を、sys.executable基準の仮想環境バイナリ優先解決により根本解決した。
8. 開発サーバーのマルチスレッド並行処理対応と切断例外抑止：
   DevServerの基盤をシングルスレッドのHTTPServerからThreadingHTTPServerへ置換し、SSE（/events）による永続ストリーム接続維持下でもブラウザからの通常リクエスト（/space, /doc, /manifest）が即座に応答する並行処理性能を確保した。また、ブラウザのリロードやタブ閉鎖に伴い発生するConnectionResetErrorおよびBrokenPipeErrorをhandle_errorにて捕捉・抑止することで、開発コンソールへのスタックトレース漏洩を根絶した。
9. ビュー切り替え時の寸法保持（visibility遷移）とSpaceリサイズ同期：
   従来のdisplay: noneによるiframe非表示処理は、要素の幅・高さを0px化してメディアクエリの誤判定（モバイル用UI化）やカメラ適合計算（fitCamera）におけるスケール極小化・メニューバーのちらつきを誘発していた。この根本原因を排除するため、非表示スタイルをvisibility: hidden; opacity: 0; pointer-events: none;へと刷新し、非アクティブ時にも実ピクセル寸法を正確に維持させた。さらに、切り替え実行時にrequestAnimationFrameを介して対象フレームのwindowへresizeイベントを能動送出し、Space側でも寸法ゼロ時のフォールバック処理を強化した。
10. Spaceへの蛍光マーカー（==）およびアンダーライン（++）機能移植：
   Doc環境でのみサポートされていたインライン強調構文（==重要=={pink} および ++下線++{cyan}）をSpace側へ完全移植した。markdown_renderer.pyにおいて名前付き正規表現グループを用いたインラインパーサーを配備し、mark要素およびspan要素へのHTML変換と色名・エイリアス解決ロジックを実装した。また、web/styles.cssにDocと完全互換のハイライトカラーパレットおよびinset box-shadow定義を追加し、単一原稿における両形式の強調表現の完全一致を確立した。
11. メニューバー（HUD）の常時表示化と自動収納制御の完全撤廃：
   スライドフォーカス時にメニューバー（HUD）を自動収納するquietモード（panel.inert = true）が、メニューの出入りによる画面のちらつきや操作不能、モード復帰時の不整合を引き起こしていた。ユーザー要求に基づき、スライドフォーカス時や全体表示時におけるメニューの自動収納処理（setMenuCollapsed）を全面的に撤廃し、画面上部のヘッダーおよび下部ツールバーを常に安定して画面上に維持する仕様へと刷新した。これにより、執筆者がどの操作を行ってもUI要素が突然消滅したり点滅したりすることなく、安定した制作・閲覧環境を確立した。
12. 親シェルヘッダー（Space/Doc切り替え）の完全固定配置とキャッシュ無効化防護：
   親シェルUI（shell/style.css）において、上部ヘッダー（#header）をposition: fixed; z-index: 9999;で画面最上部に物理固定し、ビューポートやiframeの内部スクロール・フォーカス移動によるヘッダーのはみ出し・消失を根絶した。また、親ウィンドウの不要なスクロールを（0, 0）でロックする防護リスナーを配備した。あわせて、DevServer（server.py）の全レスポンスにCache-Control: no-cache, no-store, must-revalidateヘッダーを配備し、インデックスHTMLの配信時にタイムスタンプクエリを付与することで、ブラウザキャッシュによる旧版の残存を根絶した。

## 4. テスト結果と定量的エビデンス

拡充した段階D統合テストスイート（全8件）、契約テスト（全8件）、およびSpaceテストスイート（全70件）を実行し、全件合格を確認した。

1. 開発シェルUIおよび配信ルーティングテスト（test_server_endpoints_and_shell_ui）：
   mono dev起動時に、ルートURLでMonoデザインのプレビューシェルHTMLが返され、/space, /doc, /manifestがそれぞれのコンテンツを正確に提供することを確認。
2. 完全ビルドAPI実行テスト（test_server_api_full_build_trigger）：
   POST /api/buildへのリクエストにより、完全ビルドが同期実行され、200 OKレスポンスが返却されることを確認。
3. ファイル監視テスト（test_file_watcher_detects_modification）：
   原稿ファイルのタイムスタンプ更新をFileWatcherが迅速に検知し、コールバックを実行することを確認。
4. SSEブロードキャストテスト（test_sse_broadcaster）：
   reloadイベントが購読キューへ即時配信されることを確認。
5. ポート自動フォールバックテスト（test_dev_server_auto_port_fallback）：
   ポート占有環境下において、DevServerが自動的に次の空きポートへフォールバックして正常起動することを実証。
6. ビルドロック排他制御テスト（test_build_lock_skips_concurrent_watcher_save）：
   完全ビルド実行中の保存検知が非ブロッキングロックにより安全にスキップされることを実証。
7. 見出し前プリアンブル正常ビルドテスト（test_pipeline_preamble_before_first_heading_succeeds）：
   見出し前方にキャッチコピーや情報テキストを含む原稿に対し、エラーなくSpace HTMLおよびDoc HTMLの双方が生成され、該当テキストが保持されることを実証。
8. SVGベクター画像ビルドテスト（test_pipeline_svg_image_support）：
   SVG画像を含む原稿に対し、Space HTMLへのData URL埋め込みおよびDoc HTMLへのインライン展開が正常に行われることを実証。
9. SSE接続維持下での並行HTTP応答検証（test_dev_server_threading_concurrent_sse_and_requests）：
   /eventsへのSSEストリーム接続が開かれた状態であっても、別スレッドからの/および/manifestへのリクエストが一切ブロックされず即座に応答することを実証。
10. マーカーおよびアンダーライン共通契約検証（test_shared_contract_highlight_and_underline_markup）：
   同一原稿内の==および++記法が、SpaceとDocの双方で完全に一致するクラス名・色定義のタグ構造へと相互変換されることを実証。
11. 全体表示復帰時のメニュー状態復旧検証（test_space_overview_menu_recovery_after_focus）：
   スライドフォーカスによりquietモードとなった後、全体表示操作によってquietが確実に解除され、ヘッダーおよびツールバーが操作可能状態として再展開されることを実証。
12. 全体リグレッション検証：
   Space単体テスト全70件、Docテスト全271件、段階B3契約テスト全8件、段階Cパイプラインテスト全7件、段階Dテスト全8件の合計364件の全テストが一切のエラーなく合格。

## 5. 段階Eへの引継ぎ事項

段階Dの整流化により、極めて軽量かつ堅牢なローカル制作環境が完成した。最終段階となる段階E（品質検証と実用化）に向けて、以下の項目を引き継ぐ。

1. 外部サンプル原稿による網羅的検証：
   数式（LaTeX/KaTeX）、コードブロック、大容量画像、複雑なテーブル等を含む実践的な技術ドキュメント原稿を投入し、プレビュー表示やPDF改ページ位置の崩れがないか検証する。
2. プラットフォーム互換性の確認：
   macOS環境に加えて、Linux環境におけるChromiumヘッドレス実行やファイル監視の互換性を確認する。
3. 配布パッケージングとドキュメント完備：
   CLIツールとしてのインストール手順、コマンドリファレンス、およびトラブルシューティングガイドを整備し、第三者が即座にMono Suiteを導入可能な状態を確立する。
