# Mono Space Markdown 記法ガイド

更新日：2026-09-10。操作と表示仕様は [README](../README.md)、開発状況は [DEVELOPMENT](DEVELOPMENT.md) を参照してください。

現在のエンジンで使える記法の一覧です。標準Markdownの一部と、Mono Space専用の `::` 指定に対応します。既存Monoの `@[…]` コンポーネントとは別の記法です。Mono文書は `--from mono` で限定的に変換できます（末尾参照）。

## 1. 最小の書き方

```markdown
# 発表のタイトル {#start}
発表全体の説明。

## はじめに {#intro}
この章で伝えたいこと。

### 問い {#question}
いま、何が問題になっている？

### 提案 {#proposal}
::tone primary
**新しい方法**を試してみる。
```

通常モードでは `#` は文書タイトル、`##` は横に並ぶ章、`###` は章内で縦に並ぶ話題、`####` 以下は本文内の小見出しです。`::layout` の指定は不要です。段落は空行で区切ります。連続する画像は最大3列で自動表示します。

`::layout` はその場所の子見出し配置だけを変えます。直下の見出しはH4以降でも配置要素になります。幅・段落処理は全ての文書で共通で、互換モードはありません。[document.md](../examples/standard/document.md) は配置指定なしの例です。

## 2. 早見表

| 記法 | 意味 | 省略時・条件 |
|---|---|---|
| `# 見出し` ～ `###### 見出し` | セクションを作る | 最初に見出しが必要 |
| `見出し {#my-id}` | 見出し末尾に参照用IDを付ける | 省略時は登場順に `n1`、`n2`… |
| `**強調**` | 本文の太字（マーカーなし） | 見出し内の装飾構文は未対応 |
| `[表示名](https://example.com)` | 本文のリンク。別タブで開く | HTTP / HTTPS |
| `::link https://example.com` | 横長OGPカード | 手動上書き可 |
| `::link https://example.com square` | 正方形OGPカード | 手動上書き可 |
| `` `コード` `` | 本文の短いコード表記 | 複数行はコードブロックを使用 |
| `![説明](assets/photo.png)` | ローカル画像 | PNG / JPEG / WebP / GIF |
| `::layout row` | 子を横並び | レイアウトの既定値 |
| `::layout stack` | 子を縦並び | 章内の文章配置に便利 |
| `::layout compare` | 2項目の対比／3項目の比較 | 直下の子が2個または3個 |
| `::layout flow` | 工程ボックスを矢印でつなぐ | 直下の子を文書順に横並び |
| `::tone neutral` | 通常の表示 | 色調の既定値 |
| `::tone primary` | 紫の見出しマーカー | AI・強調など |
| `::tone warning` | オレンジの見出しマーカー | 注意事項など |
| `::style note` | 黄色の付箋 | 短い補足に使用 |
| `::focus content` | 見出しと本文を拡大 | フォーカスの既定値 |
| `::focus subtree` | 子を含めた全体を拡大 | 比較・工程図に便利 |
| `::focus image` | 本文の最初の画像を拡大 | 画像がなければ本文 |
| `::connect a -> b` | ID間に接続線を描く | ラベルは任意 |
| `::connect a -> b \| 説明` | ラベル付き接続線 | 実際の入力では `\` を付けない |
| `::route a b c` | 提示順を指定 | 省略時は文書順 |

## 3. 見出し・本文・ID

見出しの階層で親子関係を決めます。インデントでの階層指定には対応していません。階層は飛ばさず記述することを推奨します。

通常モードでは空行が段落の区切りです。ソース上の連続行は同じ段落として表示します。配置指定があっても同じ処理です。

IDは見出し末尾の `{#id}` で指定します。英数字・ハイフン・アンダースコアを使うと扱いやすくなります。同じIDを複数使うと生成エラーです。

自動IDは見出しの追加や削除で変わるため、接続線や提示順から参照するセクションには明示的なIDを付けてください。明示IDと自動IDの衝突もエラーになります。

## 4. 指定を書く場所

`::layout`、`::tone`、`::focus`、`::marker` は、**直前に開いた見出しのセクション**に適用されます。見出しのすぐ下にまとめて書くと、指定先が明確になります。

```markdown
# テーマ {#topic}
## 制作プロセス {#process}
::layout flow
::focus subtree
### 観察 {#observe}
現状を調べる。
### 設計 {#plan}
解決の仮説を立てる。
### 検証 {#test}
試して、確かめる。
```

この例では `flow` と `subtree` は「制作プロセス」に適用されます。最後の「検証」の本文の後ろに指定を書くと、「検証」への指定になります。親に戻るための終了タグはありません。

指定行は行頭から書き、半角の空白・記号と小文字の値を使用してください。現状のパーサーは、指定行のインデントや余分な末尾空白を許容しません。同じセクションで同じ指定を繰り返すと、最後の値が使われます。

レイアウトは直下の子の並べ方を決めます。各セクションの指定は自動継承されません。ただし、親が `compare` や `flow` の場合は、子の幅や枠もそのレイアウトに従います。

## 5. 比較を並べる

```markdown
# 比較の例 {#comparison-demo}
## 同じ成果物、異なる視点 {#comparison}
::layout compare
::focus subtree
### 制作者 {#maker}
見た目や動作に注目する。
### 共通の成果物 {#work}
::tone primary
ウェブサイトの試作品。
### 利用者 {#reader}
目的を達成できるかに注目する。
```

子が2個なら左右同じ基本幅で上端をそろえ、3個なら記述順に左・中央・右へ配置して中央を広くします。1個や4個以上では生成エラーです。各子の中にさらにセクションを入れることはできます。

## 6. 付箋と注意事項

```markdown
# 補足の例
## 確認すること
::layout stack
### 公開前の注意
::tone warning
出典と利用条件を確認する。
### メモ
::style note
誰の、どんな問題を解くのか？
```

`normal`、`ai`、`warning` は表示する見出しマーカーの色を決めます。本文の `**強調**` は太字だけで、マーカーは付きません。`note` はセクション全体を付箋として表示します。

## 7. 画像を入れる

```markdown
# 画像の例
## 資料
::layout stack
### 図解を読む {#figure}
::focus image
![デザインの目的と制作プロセス](assets/close.png)
図解の説明文。
```

画像パスは**入力Markdownファイルのあるフォルダを基準**にします。このガイドの例は、同じフォルダにある `assets/close.png` を使用しています。

画像は縦横比を保って表示され、HTMLに埋め込まれます。同じ画像のデータは一度だけ保存するため、複数箇所に置けます。元画像が存在しない場合は生成エラー、ブラウザが画像を読み取れない場合は説明付きのエラー表示になります。

HTTPの画像URL、SVG、画像サイズやトリミングを指定するMarkdown記法は未対応です。パス中の閉じ丸括弧 `)` や、画像タイトル付き構文にも未対応です。

## 8. 拡大する範囲

| 指定 | 拡大される範囲 | 向いている内容 |
|---|---|---|
| `content` | 現在の見出しと本文。子セクションは含まない | 文章・問い・短い説明 |
| `subtree` | 現在の見出し・本文・全ての子セクション | 比較全体・工程図 |
| `image` | 現在の本文にある最初の画像 | 大きく読みたい図や写真 |

画像単体へフォーカスしても、同じセクションの見出し・文章は通常の濃さを保ちます。他のセクションは不透明度25%です。`subtree` では子セクションも通常表示します。

`image` の対象は子セクション内まで探索しません。画像がなければ本文、読み込みに失敗した画像にはエラー表示をフォーカスします。

フォーカス倍率は画面と対象の横幅から計算し、184%を上限とします。高さによる縮小は行いません。対象の上部から表示し、縦長の続きはドラッグ／2本指スクロールで確認します。俯瞰は縦横両方を収めます。Markdownからの個別倍率指定はありません。

## 9. 接続線と提示順

```markdown
# 発表 {#start}
## 判断 {#decision}
::layout stack
### 試作 {#draft}
::tone primary
まず形にする。
### 確認 {#check}
::tone warning
公開条件を確かめる。
### 公開 {#publish}
確認後に公開する。

::connect draft -> check | 公開前に確認
::connect check -> publish
::route start decision draft check publish
```

`::connect` と `::route` は文書全体への指定で、末尾にまとめて書けます。参照先が後から登場しても構いません。存在しないIDを参照すると生成エラーです。

移動は距離と倍率差に応じたパン／フェードです。「？」の「動きを抑える」またはOS設定で即時切り替えにできます。Markdownからのアニメーション指定はありません。

接続線のラベルは `|` の後ろに書きます。線は静的な関係表示であり、カメラは追尾しません。本文内の単語や画像の一部を線の起点にする指定は未対応です。

`::route` を指定しても、レイアウト上の並びは変わりません。操作UIでは重複IDを除き、未指定のセクションを文書順で末尾に追加するため、全セクションへ移動できます。複数の `::route` 行を書くと最後の行が採用されます。`0` キーは全体表示、`1`〜`9`は提示順の1〜9番目へ移動します。起動時は全体俯瞰です。

## 10. 寸法と未対応の記法

最上位の導入直下の章は、レイアウト指定にかかわらず横並びになります。章幅は600pxをグリッド単位に切り上げた値（既定では608px）以上で、内容に応じて広がります。同じキャンバス内では最も高い章に高さをそろえます。章間の間隔は既定で128pxです。寸法は `src/mono_space/web/layout.js` のグリッド・本文幅・余白密度から決まります。

座標、幅、高さ、余白、フォントサイズをMarkdownから直接指定する記法はありません。これらはエンジンのデザイン設定で管理します。

次の標準Markdown機能は、現在は構文として処理しません。

- 箇条書き・番号付きリスト：`-` や `1.` を含む通常の段落として表示。
- 斜体、取り消し線、引用、水平線。
- 数式、HTMLタグ。
- 装飾の入れ子、Markdownの汎用的なエスケープ。
- 見出し内の太字・コード・画像。
- Monoの `@[…]` コンポーネント。

HTMLコメントも非表示コメントにはならず、本文に表示されます。ソース内のコメント記法は未対応です。

## 11. HTMLの生成

`spatial` フォルダで実行します。

```sh
python3 build.py examples/standard/document.md -o dist/presentation.html
```

入力はUTF-8で保存します。Python 3.9以降の標準ライブラリだけで生成でき、完成したHTMLは単体で配布できます。このガイド自体は通常のMarkdown文書なので、生成器への入力にはせず、コード例を別の `.md` にコピーして使用してください。

## 12. テキストリンクとリッチリンク

通常リンクは `[表示名](https://example.com)` です。HTTP/HTTPSに対応し、別タブで開きます。

```markdown
# リンクの例
## 参考資料
[公式サイト](https://example.com)を参照してください。

::link https://example.com

::link https://example.com square
::link-title 手動のタイトル
::link-description 手動の説明
::link-image assets/close.png
```

`::link URL` は横長、`::link URL square` は正方形カードです。`::link-title`、`::link-description`、`::link-image` は直前のカードに適用します。通常の本文や次の見出しを書く前にまとめて指定してください。手動指定はOGPより優先します。画像の手動指定はローカルPNG/JPEG/WebP/GIFです。正方形はカード全体の形で、画像は縦横比を保ちます。

生成時にOGPタイトル・説明・画像を取得し、画像もHTMLに埋め込みます。HTMLのtitleやdescriptionもフォールバックとして使います。取得失敗時はタイトルまたはURLとドメインを表示し、画像を省略して生成を続けます。通常のテキストリンクではOGPを取得しません。

キャッシュは出力HTMLと同じフォルダの `.spatial-cache/` に保存されます。

```sh
python3 build.py examples/standard/document.md -o dist/presentation.html
python3 build.py examples/standard/document.md -o dist/presentation.html --refresh-links
python3 build.py examples/standard/document.md -o dist/presentation.html --offline
```

通常生成ではキャッシュを優先し、`--refresh-links` で再取得します。`--offline` は取得を行わず、キャッシュと手動指定だけで生成します。両方指定した場合はオフラインが優先します。

リンクのクリックでは親セクションのフォーカスは変わりません。ドラッグはキャンバス移動として扱い、リンクを開きません。フォーカス外のリンクも25%表示になります。


## 13. 見出しマーカー

通常の章見出し `##` は自動でマーカーを表示します。`#` と `###`〜`######` は既定で非表示。付箋・工程ボックス内は自動表示しません。明示指定はこれらの既定値より優先し、その見出しだけに適用されます。

```markdown
# 発表
## 章見出し
### 特に大切な問い
::marker on
::tone primary
本文の **強調** は太字のみ。
## 補足資料
::marker off
```

`::marker on`／`::marker off` で表示を指定します。色は `tone` に従います。既定の `neutral` はグレー、`primary` は紫、`warning` はオレンジ系です。帯は各行の文字の下側に重なり、複数行でも行ごとに表示されます。任意色・太さ・本文のマーカー記法は設けません。


## 14. テーブル

```markdown
# 表の例
## 比較
| 項目 | 状態 | 値 |
| :--- | :---: | ---: |
| **グリッド** | 対応 | 32px |
| 本文幅 | 対応 | 512px |
```

見出し行と区切り行の列数を一致させます。区切りは3個以上のハイフンで、`:---` は左、`:---:` は中央、`---:` は右揃えです。コロン省略時は左揃え。行の両端の `|` は省略できます。セル内の縦棒は `\|` と記述してください。

セル内で太字・インラインコード・通常リンク・画像を使用できます。縦罫線や背景塗りはなく、薄い横線で行を区切ります。列幅は内容に応じて配分し、長文は折り返します。通常モードでは、表と画像は768px、本文は最大512pxで左端をそろえます。配置指定の有無で幅は変わりません。表を含む本文の高さはグリッド配置とフォーカスの計算に反映されます。

空行で表を終えます。本文行は `|` を含む行として認識し、不足セルは空欄、余分なセルは省略します。セル結合、複数行セル、列幅の個別指定は未対応です。


### 2項目の比較例

```markdown
# 比較
## Before / After
::layout compare
::focus subtree
### Before
これまでの方法。
### After
新しい方法。
```

指定は3項目の場合と同じで、直下の子の数から自動で切り替わります。


## 15. セマンティックカラー

`tone` は色の役割、`style` は形を指定します。フレームワークを読み込まず、単一HTMLのまま使用できます。

| tone | 役割 | 基調色 |
|---|---|---|
| neutral | 標準・中立（既定） | グレー |
| primary | 主役・主要な内容 | 紫 |
| secondary | 補助的な内容 | 青紫 |
| accent | 特に区別したい内容 | 青緑 |
| info | 情報・補足 | 青 |
| success | 成功・完了 | 緑 |
| warning | 注意 | オレンジ |
| error | エラー・問題 | 赤 |

```markdown
# 発表
## 補足情報
::tone info
::style note
情報を付箋で表示する。
### 大事な内容
::tone primary
::marker on
主役として示す。
```

色は見出しマーカー・付箋背景・接続線の起点・ミニマップに反映されます。本文の文字色は読みやすい標準色を維持します。マーカーの有無は `::marker` の仕様に従い、toneだけでは小見出しのマーカーを有効にしません。

`::style plain` が既定、`::style note` が付箋です。指定はそのセクションにだけ適用されます。パレットは `src/mono_space/web/styles.css` の `--color-名前` と `--color-名前-soft` を編集して変更できます。

旧記法は互換入力として受け付けます。`normal` は `neutral`、`ai` は `primary`、`::tone note` は `::style note` と `::tone warning` に変換します。新規文書では上記の意味色を使ってください。


## 16. コード

インラインはバッククォートで囲みます。複数行は3個以上のバッククォート、またはチルダで囲みます。開始フェンスの後に `python`、`bash` などを書くと言語名を表示します。構文色分け・行番号・実行機能はありません。

````markdown
# コマンド
## 生成
`--offline` を指定します。
```bash
python3 build.py examples/standard/document.md --offline
```
````

ブロック内の `#`、`::`、HTMLなどは全てコードとして表示します。空白・改行を保持し、長い行は表示上だけ折り返します。閉じフェンスは同じ文字で開始時以上の長さにします。閉じ忘れた場合は文書末尾までコードです。

薄い背景と16pxの余白で表示し、高さをグリッド配置に反映します。コード上のドラッグは文字選択です。コピー操作は元テキストを取得します。ブラウザがクリップボード操作を許可しない場合は手動選択を案内します。コピーはホバー・フォーカス時、タッチ環境では常時表示します。


## 17. 画像を格子状に並べる

親を `stack`（段を縦に）、各段を `row`（画像を横に）とします。画像ごとに子見出しを作ります。同じ本文に画像を複数書くだけでは横並びになりません。

```markdown
## 画像ギャラリー
::layout stack
::focus subtree
### 1段目
::layout row
::focus subtree
#### 画像1
::focus image
![全体](assets/overview.png)
#### 画像2
::focus image
![詳細](assets/close.png)
```

2・3段目は `###` から同じ構造を繰り返します。横3枚にする場合は各段に `####` をもう1つ追加します。この構造を使う完成原稿は、利用する画像パスに合わせて作成してください。

画像は元の縦横比を保ちます。各段は上揃えで、高さが最も大きい画像セクションに合わせて次の段を配置します。親・段の `::focus subtree` でまとまり全体、画像の `::focus image` で1枚を拡大できます。


## 18. Mono文書からの変換

```sh
python3 build.py input.md --from mono -o dist/presentation.html --offline
```

HTMLに加え、`presentation.space.md`（変換コピー）と `presentation.conversion.json`（原文の行番号・変更内容）を生成します。元Markdownは変更しません。画像の相対パスはコピーの保存先から参照できるように書き換えます。画像はHTMLに埋め込まれますが、変換Markdownの再ビルドには参照元画像が必要です。

- `section`：囲み・任意背景色・幅の指定を除去し、内容を保持。
- `flow`：子見出しと縦配置／工程配置へ変換。
- `badge`：ラベル文字列へ変換。
- `textfield`：表示用の記入欄へ変換。入力・保存は非対応。
- `<br>`：本文では段落の区切り、見出しでは「 — 」へ変換。
- 箇条書き：中黒付き段落へ変換。水平線は除去。
- 未対応コンポーネント：原文を保持し、レポートの `unsupported` に記録。

コードブロック・インラインコード内のコンポーネント記法は変換しません。章内は縦配置を既定として補います。これはMonoの完全互換レンダラーではなく、内容を空間表示へ移すためのインポート機能です。

## 19. 役割ごとの固定幅

通常モードはセクション768px・本文の読み幅512pxです。画像・表・コードはセクション幅を使います。配置指定のある要素も同じ幅です。表のないセクションは512pxです。列数・文章量・短い最終行による幅補正は行いません。1〜2文字だけの最終行は許容し、文字サイズとフォーカス操作は維持します。


## 一時付箋

`S`キーでカーソル位置に付箋を作り、そのまま入力できます。本文をクリックして再編集、上端の「⋯」をドラッグして移動します。上端をキーボードでフォーカスすると矢印キーでも移動できます。入力中はプレゼンテーションのショートカットは無効で、Escapeで入力を終えます。

付箋はキャンバスと一緒に拡大縮小・移動します。保存・Markdownへの書き戻しは行わず、再読み込みやページを閉じると消えます。全体俯瞰の範囲・説明順・ミニマップには含めません。


数字キーは0＝全体表示、1〜9＝説明順の1〜9番目です（導入を含む）。存在しない番号は何もしません。入力中は無効です。画像フォーカスは倍率を画像幅、縦位置を所属見出しの上端で決めます。現在の上余白は画面高さの15%です。

メニューは初期展開、フォーカス移動で自動収納します。右上の「⋯」またはHで展開／収納します。俯瞰・自由探索では開閉状態を維持し、時間経過・カーソル移動では変更しません。


## Craft TextBundle（試験版）

```sh
python3 build.py "/path/to/document.textbundle" --from craft -o output/presentation.html --offline
```

`craft_import.py` はMonoとは独立した取り込みモジュールです。info.jsonとtext.markdown（またはtext.md）を読み、変換済み.space.md、複製画像の.assetsフォルダ、.conversion.jsonを出力します。元のTextBundle外を出力先に指定します。完成HTMLは画像を埋め込んだ単体ファイルです。

URLエンコードされた日本語・空白・括弧を含む画像参照に対応します。画像は単独行のローカルPNG/JPEG/WebP/GIFのみ。外部画像やバンドル外への参照はエラーにします。圧縮textpackは未対応です。

複数の最上位見出しを単一キャンバスへ整理し、章内は縦配置します。箇条書き・引用は構造を保持し、HTMLのリスト・引用として表示します。コードフェンス内は変換しません。一般Markdownの完全互換を保証するものではありません。


引用・リストの表示：Craft取り込みは元の記号を保持し、共通解析器がリスト・引用・引用内見出しへ変換します。リスト項目間24px、本文間8px、引用は浅い字下げで表示します。番号の折り返しは本文開始位置にそろいます。背景・囲み枠は追加せず、キャンバスのセクション数は増えません。一般Markdownの全仕様への対応を意味するものではありません。


## Decksetの読み込み

```sh
python3 build.py "Deckset basics.md" --from deckset -o dist/imports/deckset/presentation.html --offline
```

`---` でスライドを区切り、最初を導入、以降を章にします。コード内の区切りは保護します。スライド内の追加見出しは本文内の小見出しになります。見出しのないスライドには `Slide N` を付けます。

`![right](image.jpg)` / `![left](image.jpg)` は左右分割、`fit` / `inline` は通常の縦横比を保った画像へ変換します。単独の左右指定画像がある場合に文章と2列で表示します。複数画像は通常のギャラリーにします。元のテーマ、背景フィルター、文字自動縮小は再現しません。

発表者ノート（`^` 行）と表示設定は `.conversion.json` に保存します。動画・音声は参照名のプレースホルダーにし、元参照をレポートへ記録します。外部画像・入力フォルダー外の画像はエラーにします。画像は `.assets/` に複製し、HTMLには埋め込みます。原本は変更しません。


本文内見出し（通常のH4以降）には `::tone`・`::layout`・`::focus`・`::marker`・`::style` を指定できません。指定すると行番号付きエラーになります。話題見出しへ移すか、親に配置を明示して直下の見出しを配置要素にしてください。

Decksetからの変換Markdownには、画像の直後に `::image-position left` / `right` が出力されます。画像の説明文とは独立した配置情報です。通常の `![right](photo.png)` は説明文がrightの画像として表示します。


番号付きリストは通常の `1. 本文` で記述します。最上位の番号を薄いグレーの丸付き数字で表示し、開始番号を保持します。入れ子は通常の番号表示です。背景・影・アニメーションは付けません。


## 数式

```markdown
周期は $T = 1/f$ です。

$$
x(t) = A\sin(2\pi f t + \phi)
$$
```

本文、リスト、表のセルなどのインライン数式に対応します。見出しの数式表示は対象外です。独立数式はセクション本文に記述してください。空の数式や閉じていない独立数式はエラーです。

コード内の `$` は変換しません。通貨などの文字としてのドル記号は `\$` と記述してください。閉じるドル記号のない `$HOME` などはそのまま表示します。インライン数式は1行に収めます。

数式はSVGになり、クリックで元のTeXをコピーできます。独立数式は23px相当、本文内は本文サイズに合わせます。長い独立数式はその領域で横スクロールします。数式番号・参照・ユーザー定義マクロ・追加パッケージは対応しません。
